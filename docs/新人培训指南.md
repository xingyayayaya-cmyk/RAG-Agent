## 一、系统是什么

一个**电商领域智能客服问答系统**：用户提问后，系统自动判断意图，从知识库（商品 / 订单 / 售后政策）里检索并生成答案；遇到强情绪投诉或大额订单，自动转人工。

核心能力（对照需求）：

| 能力 | 说明 |
|---|---|
| 商品知识问答 | 500+ SKU（实际 10008 个），支持参数、价格、对比问答 |
| **组合对比问答** | "iPhone 和华为哪个续航好" 这类跨品牌对比 |
| 订单查询 | 按订单号 / 手机尾号查订单状态、金额 |
| 售后政策问答 | 多平台（淘宝/京东/拼多多/抖音/1688）退货、价保、退款政策 |
| **权限隔离** | 售前/订单/售后子 Agent 各自只能访问自己的数据源 |
| **强情绪客诉兜底** | 投诉/差评/大额订单 → 自动转人工 |

## 二、整体架构

```
用户提问
   │
   ▼
app.py（FastAPI：HTTP /api/query  或  WebSocket /api/stream）
   │
   ▼
IntegratedQASystem.query()   ── new_main.py（主类）
   │
   ▼
AgentOrchestrator.handle()   ── ecom_agent/orchestrator.py（编排器）
   │
   ├─ 1. 升级检测  EscalationAgent ── 强情绪 / 大额订单 → 转人工话术
   ├─ 2. FAQ 快速通道  BM25Search ── 相似度 ≥ 0.85 → 直接返回 FAQ 答案
   ├─ 3. 意图路由  IntentRouter ── 规则优先，未命中再 LLM 兜底
   │        ├─ 售前 → PresaleAgent   → RAG 检索（source="product" 商品库）
   │        ├─ 订单 → OrderAgent     → 查订单表（SQLite/MySQL）
   │        ├─ 售后 → AftersaleAgent → RAG 检索（source="policy" 售后政策库）
   │        └─ 闲聊 → LLM 直答
   └─ 4. 流式返回 (token, is_complete) + 写对话历史
```

**RAG 检索链**（售前/售后共用）：混合检索（稠密 BGE-M3 + 稀疏 BM25）→ Rerank（bge-reranker）→ 父子块去重 → LLM 生成，并支持 HyDE、子查询增强。

## 三、技术栈

| 层 | 技术 |
|---|---|
| Web 框架 | FastAPI + WebSocket |
| 向量库 | Milvus（远程）；本地降级用自写 `LocalVectorStore`（numpy 暴力检索 + pickle 持久化） |
| 关系库 | MySQL（远程）；本地降级 SQLite |
| 缓存 | Redis（远程）；本地降级 `MemoryCache`（进程内 dict） |
| 检索 | 稠密 BGE-M3 + 稀疏 BM25 + bge-reranker-large |
| 大模型 | DeepSeek（OpenAI 兼容 SDK，流式） |
| 语言 | Python 3.10（conda 环境 `EduRAG`） |

## 八、怎么用

### 方式 1：前端界面（推荐，新手测试用）

浏览器打开 `http://localhost:18080/`，直接对话即可。

### 方式 2：HTTP 接口（非流式，问候/FAQ 命中时用）

```bash
curl -X POST http://localhost:18080/api/query \
  -H "Content-Type: application/json" \
  -d '{"query": "七天无理由退货政策是什么", "session_id": "test-001"}'
```

### 方式 3：WebSocket（流式，走完整 RAG/Agent 链路）

连接 `/api/stream`，发送 `{"query": "...", "session_id": "..."}`，服务端依次返回：

| type | 含义 |
|---|---|
| `start` | 开始处理 |
| `token` | 流式输出片段（`token` 字段） |
| `end` | 结束（`is_complete: true`，含 `processing_time`） |
| `error` | 出错（`error` 字段） |

> 每个 WebSocket 连接处理**一条**查询后即关闭，下一条需重新连接。

### 会话历史

- 新建会话：`POST /api/create_session`
- 查历史：`GET /api/history/{session_id}`
- 清历史：`DELETE /api/history/{session_id}`

## 九、核心功能原理（重点理解）

### 1. 意图路由（`router.py`）

- **规则优先**：正则/关键词匹配（订单号 `ORD...`、手机尾号、SKU、意图关键词），快且离线可用。
- **LLM 兜底**：规则未命中时，用 DeepSeek 分类到 `售前/订单/售后/闲聊`。
- 映射：售前→presale、订单→order、售后→aftersale、闲聊→chitchat。

### 2. 权限隔离（每个子 Agent 只拿自己的数据）

| 子 Agent | 数据源 | 说明 |
|---|---|---|
| PresaleAgent | RAG `source="product"` | 只能查商品库 |
| AftersaleAgent | RAG `source="policy"` | 只能查售后政策库 |
| OrderAgent | 订单表（`lookup_order`） | 只能查订单 |

每个 Agent 的 `tools`/`source_filter` 是**硬编码**的，无法访问其他 Agent 的数据源——这是权限隔离的物理保证。

### 3. 升级转人工（`escalation_agent.py`）

在路由前执行，命中即返回转人工话术（含 ticket 号 + 客服电话），不再进子 Agent：
- **强情绪关键词**：投诉、差评、退款、垃圾、欺骗、12315、起诉、报警、气死…
- **大额订单**：query 含订单号/手机号 → 查订单金额 ≥ 平台阈值（淘宝 5000 / 京东 10000 / 拼多多 3000 / 抖音 8000 / 1688 20000）。

### 4. FAQ 快速通道（`bm25_search.py`）

用 BM25 对 FAQ 问题库算相似度，**≥ 0.85** 直接返回现成答案（快、不耗 LLM）；否则回退 RAG。

### 5. RAG 检索链

1. 混合检索：稠密向量（BGE-M3）+ 稀疏向量，加权合并；
2. Rerank：bge-reranker 精排；
3. 父子块：子块精确召回 → 父块还原完整上下文；
4. 可选增强：HyDE（假设性文档）、子查询拆分；
5. LLM 按子 Agent 的提示词生成答案。

## 十、配置与切换（本地 / 远程）

`base/config.ini` 里 `local_mode`：

- `local_mode = true`（默认）：SQLite + MemoryCache + LocalVectorStore，**无需远程基础设施**，适合本地开发测试。
- `local_mode = false`：切回远程 MySQL / Redis / Milvus（`192.168.21.226`），生产用。

## 十一、常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 大模型调用返回 401/连接失败 | 未走代理，先 `export https_proxy=http://127.0.0.1:7897` |
| 前端连不上后端 | 确认服务在 18080 端口、`/health` 通；跨域已开 CORS |
| 回答变慢 | 商品向量化/检索耗 GPU/内存，属正常；FAQ 命中时会很快 |
| 重灌后数据翻倍 | 灌库脚本是追加式，重灌前先删 `data/ecom.db`、`data/local_vec_meta.pkl` |
| 中文日志乱码 | 控制台 GBK 显示问题，数据本身无损；可 `export PYTHONUTF8=1` |
| 检索召回不相关商品 | 检查 query 与知识库用词是否对齐（品牌/类目/属性） |
