### 2.1 DianJin 中文客服对话 —— 强情绪检测的核心

- 来源：`DianJin/DianJin-CSC-Data`（Hugging Face）
- 文件：`05_客服对话_多轮_dialog/dianjin/data/CSConv.json`(8.7 MB) / `RoleCS.json`(64 MB)
- 标注：客服 / 客户角色 + **18 种情绪服务策略**
- 价值：策略标注中已含「礼貌问候 / 确认身份 / **情绪安抚** / **转移升级**」——这四类几乎就是风控升级 Agent 的行为标签，可以直接拿来校准情绪分级与升级触发规则

### 2.2 Full-Ecom-Chatbot —— 多 Agent 编排的现成结构参考

- 来源：`rescommons/Full-Ecom-Chatbot-Dataset`（Hugging Face）
- 文件：`05_客服对话_多轮_dialog/full_ecom_chatbot/data/`（train 19 MB / test 4.8 MB）
- 字段亮点：`prompt` / `history` / **`tools`（函数定义）** / `response_type`(tool_call) / **`intent_category`**（如 `returns_exchanges`）/ `intent` / `sub_intent` / `domain` / `context`（含 `order_details`）
- 价值：**这套 `tools + intent_category + context.order_details` 的三段式结构，正是我们要建的 agent 编排层的设计蓝本**——尤其 `tools` 的函数定义格式，可以直接对标 `adapters/` 层的接口设计
- 注意：英文为主，借鉴结构，中文业务数据用合成补齐

### 2.3 Chinese-EcomQA / Ecommerce_FAQ —— 样式与格式参考

- Chinese-EcomQA：1,800 条品牌 / 类目 / 意图问答，作商品知识问答的样式参考
- Ecommerce_FAQ：79 条（账户 / 订单 / 支付 / 物流 / 退货），量小，仅作 FAQ 字段格式样例

## 5. 关键判断：为什么数据偏少不影响进度

这是本轮最重要的结论，值得单独讲清楚。

| 层 | 内容 | 来源 | 状态 |
|---|---|---|---|
| **语料层** | 多轮对话、情绪、意图、FAQ 格式 | **开源下载** | ✅ 已完成 |
| **业务知识层** | 商品库、订单、售后政策 | **合成 / 构造** | ⏳ 下一步（本来就要做） |

**逻辑**：业务知识库（商品/订单/政策）**本来就没有可用的开源数据**，从调研阶段就确定要合成/构造——它才是系统主体。而开源能补的正是"对话/情绪/意图"这类通用语料，这批已经到手。

所以：**缺的那几个数据集，缺的都恰好是"锦上添花"的部分；非缺不可的部分，一个都没缺。**

## 7. 风险与注意事项

| 风险 | 应对 |
|---|---|
| Full-Ecom-Chatbot 为英文，字段语义与中文业务有偏差 | 只借鉴结构（tools / intent_category / context），不直接用其内容 |
| DianJin 为通用客服域，未必覆盖电商话术 | 与合成的商品/订单数据组合使用，不单独做业务知识源 |
| 合成数据分布与真实偏差，评测可能虚高 | 评测集标注数据来源；M3 引入真实数据校准 |
| 商品库 pickle 类数据反序列化风险（如后续引入 JDivPS） | 隔离环境执行，只读不执行未知代码 |
| 数据授权 | 逐份核对 License；本批 4 个数据集用途限定为开发/演示 |
